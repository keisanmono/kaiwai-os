# 实验 0-4：多任务并发执行

在实验 0-3 的 RISC-V 裸机内核基础上，实现两个用户态任务和协作式轮转调度。任务在 `yield` 或 `exit` 时切换；这不是时钟驱动的抢占式调度。

## 构建与运行

需要 `riscv64-unknown-elf-gcc`、QEMU 的 `qemu-system-riscv64` 和 Python 3：

```sh
make
make run
make test
```

`make run` 使用 QEMU virt、单核、无固件启动；任务全部退出后 QEMU 自动结束。`make test` 检查任务交替顺序、两次退出及 PASS，任务自身还在让出后检查寄存器与用户栈。若要使用其他工具链前缀或 QEMU，可以设置 `CROSS` 或 `QEMU`。

## 设计

- `kernel.h` 定义 PCB：PID、名称、状态、上下文指针、用户栈和内核栈顶。每个任务各有 4 KiB 用户栈和 4 KiB 内核栈。
- `start.S` 从 M 态进入 S 态；陷入时在当前任务的内核栈保存全部通用寄存器、`sepc` 和 `sstatus`，然后由调度器选择要恢复的帧。内核函数调用期间的寄存器无需跨任务保留，因为每次调度均从完整的用户陷入帧返回。
- `kernel.c` 实现 READY、RUNNING、EXITED 状态和循环扫描；`puts`、`yield`、`exit` 分别使用调用号 2、3、4，不支持的调用返回 -1。
- `user.S` 的 alpha 和 beta 分别保留不同的寄存器及栈值，交替输出三步并检查恢复结果。日志中的姓名和学号沿用前一实验的项目标记。

## 范围

本实验采用单核、关中断的协作式调度；任务只有主动调用 `yield` 或 `exit` 才会切换，没有实现时钟抢占或锁。用户程序与内核共享物理地址空间，内核信任内置程序及其传入指针，不提供进程间内存隔离。若扩展为抢占或多核，需增加定时器与同步机制，并重新处理内核态中断和访问保护。
